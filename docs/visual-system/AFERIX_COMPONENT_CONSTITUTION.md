# AFERIX — COMPONENT CONSTITUTION

**STATUS: FROZEN | RATIFIED | DESIGN AUTHORITY**
**VERSION: 1.0**

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## PART 1 — COMPONENT PHILOSOPHY
Components exist to serve the following priorities (in order):
1. **Speed** (Interaction time)
2. **Clarity** (Cognitive load)
3. **Revenue** (Call to action)
4. **Execution** (Technical accuracy)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## PART 2 — BUTTON SYSTEM
*   **P0 (Primary):** Large, Aferix Gold background, Black text. High-elevation. Only one per screen.
*   **P1 (Secondary):** Outline or Ghost style. Medium weight.
*   **P2 (Utility):** Icon-only or small text. Subtle.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## PART 3 — CARD SYSTEM (THE UNIVERSAL LANGUAGE)
*   **TYPE A (Attention):** Border: 2px Aferix Gold/Red. Shadow: Level 2. Background: Elevated.
*   **TYPE B (Operational):** Border: Subtle. Shadow: Level 1. Background: Surface.
*   **TYPE C (Information):** No border. Shadow: None. Background: Transparent/Subtle.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## PART 4 — LIST & SEARCH SYSTEM
*   **Swipe Actions:** Left Swipe = Delete/Archive. Right Swipe = Duplicate/Copy.
*   **Selection:** Single-tap to open; Long-press for multi-select.
*   **Search:** Always pinned to the top of module lists. Shows "Recent Searches" by default.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## PART 5 — ERROR & SYNC STATES
*   **Errors:** Use "Technical Failure" (Amber) or "System Block" (Red). Always provide a "Tentar Novamente" button.
*   **Sync States:**
    *   **Synced:** Subtle green check/dot in status bar.
    *   **Pending:** Cloud icon with arrow. 
    *   **Conflict:** P0 Attention Card on Home.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## PART 6 — FORM SYSTEM (MAXIMUM SPEED)
*   **Numeric Inputs:** Auto-focus numeric keyboard for prices/quantities.
*   **Bottom Sheets:** Used for 100% of "Pickers" (Client picker, Material picker).
*   **Currency:** Auto-masking (R$ 0,00) is mandatory.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## PART 7 — CONSTITUTIONAL LAWS
1.  **LAW #01:** Consistency outranks creativity. Use existing components only.
2.  **LAW #02:** If a component doesn't help the technician work faster, it is visual waste.
3.  **LAW #04:** Every empty state must have an "Action Button" (The "What's Next" rule).
4.  **LAW #05:** One primary action (P0) per screen.
