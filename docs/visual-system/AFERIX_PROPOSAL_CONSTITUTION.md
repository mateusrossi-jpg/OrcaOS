# AFERIX — PROPOSAL EXPERIENCE CONSTITUTION

**STATUS: RATIFIED | VERSION: 1.0**
**AUTHORITY: PRODUCT CONSTITUTION**

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## CORE PRINCIPLE

The Proposal is not a PDF.
The Proposal is not a document.
The Proposal is a **Revenue Conversion Experience**.

The Proposal exists to maximize trust, understanding, and approval probability.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## OFFICIAL RULE: DELIVERY MODEL

1.  **PRIMARY: Live Proposal** (Canonical Experience)
2.  **SECONDARY: PDF Export** (Portable Representation)

The Live Proposal is the source of truth. The PDF is a subset. The objective is approval, not document generation.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## CUSTOMER JOURNEY

Technician creates Proposal → Client receives WhatsApp link → Client opens Live Proposal → Client understands problem → Client understands solution → Client understands value → Client approves → Proposal becomes Work Order.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## LIVE PROPOSAL REQUIREMENTS

The Live Proposal must:
• Open instantly on mobile (no login/no app installation).
• Be responsive and shareable.
• Be printable and exportable.
• Preserve absolute professionalism and trust.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## TRUST HIERARCHY (ORDER OF INFORMATION)

Price must never be the first thing shown. Trust must be built before price.

1.  Company Identity
2.  Technician Credibility
3.  Problem Evidence (Photos)
4.  Proposed Solution
5.  Deliverables
6.  Warranty
7.  Timeline
8.  **Investment Value (Price)**
9.  **Approval Action (P0 Button)**

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## OFFLINE-FIRST COMPATIBILITY

• Proposal creation and editing must work offline for the technician.
• Local data is authoritative until synchronization.
• The cloud exists for sharing and synchronization, not for permission to work.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## DIRECTIVES FOR IMPLEMENTATION

**CODEx:** Optimize for approval rate, trust generation, and mobile speed.
**ANTIGRAVITY:** Every proposal feature must answer: *"Will this increase proposal approval probability?"*

━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## FINAL PRODUCT TRUTH

The customer does not buy a proposal; the customer buys **confidence**.
The technician does not pay for software; the technician pays for a **higher probability of winning work**.

**AFERIX SHALL TREAT THE PROPOSAL AS A REVENUE ENGINE. THE ERP EXISTS TO SUPPORT THAT MOMENT.**
